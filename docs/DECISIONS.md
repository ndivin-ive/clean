# Technical decisions

One line per decision: **what** — _why_. Newest at the bottom. "Q" items answer
the open questions from the Phase 1 plan; the product owner said "use the
brief", so the proposed defaults below were adopted and can be revisited.

| ID    | Decision                                                                                                                                                                                                 | Reason                                                                                                                                                                                                                |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | **Drizzle ORM** (not Prisma)                                                                                                                                                                             | SQL-first; RLS policies and roles can be declared in the schema; easy per-transaction `set_config` for tenant context. Ref: https://orm.drizzle.team/docs/rls                                                         |
| D-002 | **Two DB roles**: `clean_owner` runs migrations; app connects as `clean_app` (NOSUPERUSER, NOBYPASSRLS, owns nothing); tables use `FORCE ROW LEVEL SECURITY`                                             | Superusers, BYPASSRLS roles and table owners skip RLS by default. Ref: https://www.postgresql.org/docs/16/ddl-rowsecurity.html                                                                                        |
| D-003 | Tenant context = `set_config('app.org_id', …, true)` inside a transaction per request; policies compare `organization_id` to it; unset ⇒ zero rows                                                       | Transaction-local setting cannot leak across pooled connections. Ref: https://www.postgresql.org/docs/16/functions-admin.html                                                                                         |
| D-004 | **`cacheComponents` off** in Next.js 16                                                                                                                                                                  | Nearly every screen is per-user, per-tenant; opt-in caching risks serving one tenant's data to another. Revisit for public pages only.                                                                                |
| D-005 | **Next.js 16.4** App Router; `src/proxy.ts` (Next 16 renamed middleware → proxy)                                                                                                                         | Current stable; brief stack.                                                                                                                                                                                          |
| D-006 | **next-intl 4**, locale-prefixed routes `/en`, `/fr`; typed message keys                                                                                                                                 | Brief stack; type errors for missing keys.                                                                                                                                                                            |
| D-007 | ESLint `react/jsx-no-literals` on `src/app` and `src/components` + unit test that EN/FR catalogues have identical keys, valid ICU and same placeholders                                                  | Enforces rule 3 mechanically.                                                                                                                                                                                         |
| D-008 | ESLint `no-restricted-imports` bans AI provider SDKs outside `src/server/ai/`                                                                                                                            | Enforces rule 5 mechanically.                                                                                                                                                                                         |
| D-009 | `src/domain/**` must not import framework, DB or server code (lint rule)                                                                                                                                 | Keeps `assess()`, state machine and permissions pure and reusable by the Phase 3 MCP server.                                                                                                                          |
| D-010 | Single Next.js app (no monorepo) in Phase 1                                                                                                                                                              | Less tooling; domain code is already isolated and can move to `packages/` later.                                                                                                                                      |
| D-011 | **TypeScript 5.9** (not 7.x)                                                                                                                                                                             | `typescript-eslint` 8.x supports TS `<6.1`.                                                                                                                                                                           |
| D-012 | System font stack, no Google Fonts                                                                                                                                                                       | No third-party font request (EU-first); works offline/in sandboxes.                                                                                                                                                   |
| D-013 | UI primitives written in-repo in the shadcn/ui style (Tailwind tokens, Radix primitives where needed) instead of the shadcn CLI                                                                          | Same result (shadcn is copy-in source); CLI registry not required.                                                                                                                                                    |
| D-014 | **Mailpit** as local mail catcher                                                                                                                                                                        | Maintained; HTTP API lets Playwright read magic links. Ref: https://mailpit.axllent.org/                                                                                                                              |
| D-015 | Vitest projects `unit` and `integration` (real PostgreSQL, serial); Playwright e2e against `next start` in CI                                                                                            | Brief stack; RLS can only be proven against real Postgres.                                                                                                                                                            |
| D-016 | `scripts/local-pg.sh` starts PostgreSQL 16 without Docker                                                                                                                                                | Some dev/CI sandboxes have no Docker daemon.                                                                                                                                                                          |
| D-017 | `PW_CHROMIUM_PATH` optional override in Playwright config                                                                                                                                                | Reuse a pre-installed Chromium where downloads are blocked.                                                                                                                                                           |
| Q1    | Auth identity tables (`user`, `auth_account`, `session`, `verification_token`) are **global**; everything with business data carries `organization_id` under RLS; `membership` links user ↔ organization | A person can belong to several organizations; identity tables hold no business data.                                                                                                                                  |
| Q2    | Sales teams via **`membership.manager_id`** (manager sees direct and indirect reports' deals)                                                                                                            | Smallest model that answers "their team".                                                                                                                                                                             |
| Q3    | Engagement status gains **`draft`** before `new` (visible to requester only)                                                                                                                             | Autosaved drafts need a home.                                                                                                                                                                                         |
| Q4    | Add tables **`invitation`**, **`notification`**, **`engagement_type`**                                                                                                                                   | Implied by invitations, in-app notifications and per-function engagement types.                                                                                                                                       |
| Q5    | RLS enforces the **tenant** boundary; role scoping (own / team / supported / function) is enforced in the service layer by `can()` + query scopes, with tests                                            | Keeps policies simple and reviewable.                                                                                                                                                                                 |
| Q6    | Google and Microsoft sign-in coded but **disabled unless env vars set**; Phase 1 tests use magic link                                                                                                    | OAuth app registrations are accounts (stop-and-ask rule).                                                                                                                                                             |
| Q7    | Working days = Monday–Friday; no holiday calendar in Phase 1                                                                                                                                             | Simple and predictable; org holiday list later.                                                                                                                                                                       |
| Q8    | Amount + currency per opportunity; totals grouped by currency, no FX                                                                                                                                     | No FX source in Phase 1.                                                                                                                                                                                              |
| Q9    | One commit (or a few) per checkpoint on the working branch; PR only on request                                                                                                                           | Small, reviewable steps.                                                                                                                                                                                              |
| D-018 | **Better Auth 1.7** instead of Auth.js (approved by product owner)                                                                                                                                       | Auth.js v5 is still beta (`npm view next-auth dist-tags`: latest 4.24.15, beta 5.0.0-beta.32); Better Auth is stable, supports magic link, Google, Microsoft and a Drizzle adapter. Ref: https://www.better-auth.com/ |
| D-019 | Auth tables prefixed `auth_` and keyed by UUID (`advanced.database.generateId: "uuid"`)                                                                                                                  | Better Auth's `account` model would collide with the CRM `account` table; UUIDs everywhere.                                                                                                                           |
| D-020 | **Composite foreign keys** `(organization_id, x_id) → parent(organization_id, id)`; user references go to `membership(organization_id, user_id)`                                                         | PostgreSQL FK checks bypass RLS, so a single-column FK would let tenant B reference tenant A's rows or users.                                                                                                         |
| D-021 | Audit via `audit_row()` trigger (SECURITY DEFINER) on every tenant table; app role has SELECT-only on `audit_event`; secret columns redacted; no-op updates skipped; global auth tables not audited      | "Every write is recorded" without relying on application code; tamper-resistant from the app. Session/verification churn is not business data.                                                                        |
| D-022 | `organization.organization_id` is a generated column equal to `id`                                                                                                                                       | One policy and one trigger shape for every tenant table.                                                                                                                                                              |
| D-023 | Two read-only extra policies: a user sees their own `membership` rows and the `organization`s they belong to without a tenant selected                                                                   | Needed for the organization picker after sign-in; writes still require tenant context.                                                                                                                                |
| D-024 | `clean_enable_tenant_table(regclass)` SQL helper applies RLS, policy, triggers and grants; a catalogue test fails if any table with `organization_id` lacks them                                         | New tables cannot silently skip isolation.                                                                                                                                                                            |
| D-025 | `account.owner_id` added (not in brief's data model)                                                                                                                                                     | Required by the role matrix ("create / edit own accounts").                                                                                                                                                           |
