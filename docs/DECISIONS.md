# Technical decisions

One line per decision: **what** — _why_. Newest at the bottom. "Q" items answer
the open questions from the Phase 1 plan; the product owner said "use the
brief", so the proposed defaults below were adopted and can be revisited.

| ID    | Decision                                                                                                                                                                                                                                                                                                                          | Reason                                                                                                                                                                                                                |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | **Drizzle ORM** (not Prisma)                                                                                                                                                                                                                                                                                                      | SQL-first; RLS policies and roles can be declared in the schema; easy per-transaction `set_config` for tenant context. Ref: https://orm.drizzle.team/docs/rls                                                         |
| D-002 | **Two DB roles**: `clean_owner` runs migrations; app connects as `clean_app` (NOSUPERUSER, NOBYPASSRLS, owns nothing); tables use `FORCE ROW LEVEL SECURITY`                                                                                                                                                                      | Superusers, BYPASSRLS roles and table owners skip RLS by default. Ref: https://www.postgresql.org/docs/16/ddl-rowsecurity.html                                                                                        |
| D-003 | Tenant context = `set_config('app.org_id', …, true)` inside a transaction per request; policies compare `organization_id` to it; unset ⇒ zero rows                                                                                                                                                                                | Transaction-local setting cannot leak across pooled connections. Ref: https://www.postgresql.org/docs/16/functions-admin.html                                                                                         |
| D-004 | **`cacheComponents` off** in Next.js 16                                                                                                                                                                                                                                                                                           | Nearly every screen is per-user, per-tenant; opt-in caching risks serving one tenant's data to another. Revisit for public pages only.                                                                                |
| D-005 | **Next.js 16.4** App Router; `src/proxy.ts` (Next 16 renamed middleware → proxy)                                                                                                                                                                                                                                                  | Current stable; brief stack.                                                                                                                                                                                          |
| D-006 | **next-intl 4**, locale-prefixed routes `/en`, `/fr`; typed message keys                                                                                                                                                                                                                                                          | Brief stack; type errors for missing keys.                                                                                                                                                                            |
| D-007 | ESLint `react/jsx-no-literals` on `src/app` and `src/components` + unit test that EN/FR catalogues have identical keys, valid ICU and same placeholders                                                                                                                                                                           | Enforces rule 3 mechanically.                                                                                                                                                                                         |
| D-008 | ESLint `no-restricted-imports` bans AI provider SDKs outside `src/server/ai/`                                                                                                                                                                                                                                                     | Enforces rule 5 mechanically.                                                                                                                                                                                         |
| D-009 | `src/domain/**` must not import framework, DB or server code (lint rule)                                                                                                                                                                                                                                                          | Keeps `assess()`, state machine and permissions pure and reusable by the Phase 3 MCP server.                                                                                                                          |
| D-010 | Single Next.js app (no monorepo) in Phase 1                                                                                                                                                                                                                                                                                       | Less tooling; domain code is already isolated and can move to `packages/` later.                                                                                                                                      |
| D-011 | **TypeScript 5.9** (not 7.x)                                                                                                                                                                                                                                                                                                      | `typescript-eslint` 8.x supports TS `<6.1`.                                                                                                                                                                           |
| D-012 | System font stack, no Google Fonts                                                                                                                                                                                                                                                                                                | No third-party font request (EU-first); works offline/in sandboxes.                                                                                                                                                   |
| D-013 | UI primitives written in-repo in the shadcn/ui style (Tailwind tokens, Radix primitives where needed) instead of the shadcn CLI                                                                                                                                                                                                   | Same result (shadcn is copy-in source); CLI registry not required.                                                                                                                                                    |
| D-014 | **Mailpit** as local mail catcher                                                                                                                                                                                                                                                                                                 | Maintained; HTTP API lets Playwright read magic links. Ref: https://mailpit.axllent.org/                                                                                                                              |
| D-015 | Vitest projects `unit` and `integration` (real PostgreSQL, serial); Playwright e2e against `next start` in CI                                                                                                                                                                                                                     | Brief stack; RLS can only be proven against real Postgres.                                                                                                                                                            |
| D-016 | `scripts/local-pg.sh` starts PostgreSQL 16 without Docker                                                                                                                                                                                                                                                                         | Some dev/CI sandboxes have no Docker daemon.                                                                                                                                                                          |
| D-017 | `PW_CHROMIUM_PATH` optional override in Playwright config                                                                                                                                                                                                                                                                         | Reuse a pre-installed Chromium where downloads are blocked.                                                                                                                                                           |
| Q1    | Auth identity tables (`user`, `auth_account`, `session`, `verification_token`) are **global**; everything with business data carries `organization_id` under RLS; `membership` links user ↔ organization                                                                                                                          | A person can belong to several organizations; identity tables hold no business data.                                                                                                                                  |
| Q2    | Sales teams via **`membership.manager_id`** (manager sees direct and indirect reports' deals)                                                                                                                                                                                                                                     | Smallest model that answers "their team".                                                                                                                                                                             |
| Q3    | Engagement status gains **`draft`** before `new` (visible to requester only)                                                                                                                                                                                                                                                      | Autosaved drafts need a home.                                                                                                                                                                                         |
| Q4    | Add tables **`invitation`**, **`notification`**, **`engagement_type`**                                                                                                                                                                                                                                                            | Implied by invitations, in-app notifications and per-function engagement types.                                                                                                                                       |
| Q5    | RLS enforces the **tenant** boundary; role scoping (own / team / supported / function) is enforced in the service layer by `can()` + query scopes, with tests                                                                                                                                                                     | Keeps policies simple and reviewable.                                                                                                                                                                                 |
| Q6    | Google and Microsoft sign-in coded but **disabled unless env vars set**; Phase 1 tests use magic link                                                                                                                                                                                                                             | OAuth app registrations are accounts (stop-and-ask rule).                                                                                                                                                             |
| Q7    | Working days = Monday–Friday; no holiday calendar in Phase 1                                                                                                                                                                                                                                                                      | Simple and predictable; org holiday list later.                                                                                                                                                                       |
| Q8    | Amount + currency per opportunity; totals grouped by currency, no FX                                                                                                                                                                                                                                                              | No FX source in Phase 1.                                                                                                                                                                                              |
| Q9    | One commit (or a few) per checkpoint on the working branch; PR only on request                                                                                                                                                                                                                                                    | Small, reviewable steps.                                                                                                                                                                                              |
| D-018 | **Better Auth 1.7** instead of Auth.js (approved by product owner)                                                                                                                                                                                                                                                                | Auth.js v5 is still beta (`npm view next-auth dist-tags`: latest 4.24.15, beta 5.0.0-beta.32); Better Auth is stable, supports magic link, Google, Microsoft and a Drizzle adapter. Ref: https://www.better-auth.com/ |
| D-019 | Auth tables prefixed `auth_` and keyed by UUID (`advanced.database.generateId: "uuid"`)                                                                                                                                                                                                                                           | Better Auth's `account` model would collide with the CRM `account` table; UUIDs everywhere.                                                                                                                           |
| D-020 | **Composite foreign keys** `(organization_id, x_id) → parent(organization_id, id)`; user references go to `membership(organization_id, user_id)`                                                                                                                                                                                  | PostgreSQL FK checks bypass RLS, so a single-column FK would let tenant B reference tenant A's rows or users.                                                                                                         |
| D-021 | Audit via `audit_row()` trigger (SECURITY DEFINER) on every tenant table; app role has SELECT-only on `audit_event`; secret columns redacted; no-op updates skipped; global auth tables not audited                                                                                                                               | "Every write is recorded" without relying on application code; tamper-resistant from the app. Session/verification churn is not business data.                                                                        |
| D-022 | `organization.organization_id` is a generated column equal to `id`                                                                                                                                                                                                                                                                | One policy and one trigger shape for every tenant table.                                                                                                                                                              |
| D-023 | Two read-only extra policies: a user sees their own `membership` rows and the `organization`s they belong to without a tenant selected                                                                                                                                                                                            | Needed for the organization picker after sign-in; writes still require tenant context.                                                                                                                                |
| D-024 | `clean_enable_tenant_table(regclass)` SQL helper applies RLS, policy, triggers and grants; a catalogue test fails if any table with `organization_id` lacks them                                                                                                                                                                  | New tables cannot silently skip isolation.                                                                                                                                                                            |
| D-025 | `account.owner_id` added (not in brief's data model)                                                                                                                                                                                                                                                                              | Required by the role matrix ("create / edit own accounts").                                                                                                                                                           |
| D-026 | **Default pipeline stages** (seeded by the setup wizard, editable): Lead / prospect · Discovery · Solution / demo · Proposal / evaluation · Negotiation · Closed won · Closed lost. Each stage carries an **exit criterion** (EN/FR) and a **target age in days**.                                                                | Product owner guidance: ordered steps with a clear hand-off and measurable progression; avoid stages sellers do not use consistently.                                                                                 |
| D-027 | **Pipeline visualisation = horizontal stage-by-stage bars**, not a funnel. Shows value or count per stage, stage-to-stage conversion, average age vs target and stalled deals; optional colour by owner or segment; table view. Funnel only for a high-level narrative, never as the operational view.                            | Deals skip stages and re-enter earlier ones; a funnel implies a smooth narrowing that does not exist.                                                                                                                 |
| D-028 | **Manager dashboard layout**: KPIs (total pipeline, weighted pipeline, win rate, average deal size, sales-cycle length) → stage chart → conversion view → action view (stalled beyond target age, next step overdue, close date approaching) → forecast by expected close month and probability band.                             | Product owner guidance; prototyped in `prototype/clean-uat.html` (v4). Scope change: brings part of Phase 2 analytics into Phase 1, pending confirmation.                                                             |
| D-029 | Conversion rate for stage _i_ = deals that reached stage _i+1_ (or won) ÷ deals that reached stage _i_, computed from `opportunity_stage_event`, open and closed deals included.                                                                                                                                                  | Transparent and reproducible from stored events (rule 4: scores show why). Open deals still in a stage lower the rate; stated on the chart.                                                                           |
| D-030 | Chart colours: one hue (accent) for single-series bars; reference categorical palette slots 1–6 for colour-by-owner/segment; ordinal blue ramp `#6da7ec → #2a78d6 → #104281` for probability bands. All validated with the dataviz palette validator (light mode).                                                                | Colour-blind-safe and consistent; weak-contrast slots are relieved by legend, tooltips and table view.                                                                                                                |
| D-031 | **Pivot to the sales companion** (product owner, 20 Nov 2026). Support booking collapsed into one `support_request` table behind flag `support_requests` (off).                                                                                                                                                                   | Brief v2; the old module existed only as schema. See `PIVOT.md`.                                                                                                                                                      |
| D-032 | Roles: **seller, manager, admin**; `specialist` only for the parked module.                                                                                                                                                                                                                                                       | Smallest set the companion needs; AE vs AM behave the same in Phase 1.                                                                                                                                                |
| D-033 | **Owner privacy in PostgreSQL**: seller-owned tables carry `owner_id`; RESTRICTIVE policies allow read to the owner, or — when `organization.team_visibility` is on — to teammates (same manager) and the management chain; writes owner-only; **admins get no implicit access**. Notifications readable by their recipient only. | Rule 2 enforced at the data layer, tested per table (supersedes Q5).                                                                                                                                                  |
| D-034 | `interaction_participant` join table: exactly one of a person (customer side) or a member (colleague).                                                                                                                                                                                                                            | Every participant is tenant- and owner-safe through composite FKs; "who from our side" is visible.                                                                                                                    |
| D-035 | Qualification stored as one `deal_qualification` row per deal × criterion (not a JSON blob); changes logged in `deal_event`.                                                                                                                                                                                                      | Per-criterion evidence, events and FK to the configurable criteria set.                                                                                                                                               |
| D-036 | New table `close_plan_step` (deal, title, buyer/seller owner, due date, done).                                                                                                                                                                                                                                                    | Required by Phase 1 §6.3, missing from §4.                                                                                                                                                                            |
| D-037 | **AI off in Phase 1**: gateway, settings table and a test provider only; no paid model account.                                                                                                                                                                                                                                   | Stop-and-ask rule; every feature works on rules.                                                                                                                                                                      |
| D-038 | Forecast period = quarter, aligned to `organization.fiscal_year_start_month` (default January).                                                                                                                                                                                                                                   | Common default, configurable.                                                                                                                                                                                         |
| D-039 | "Not relevant (teach)" multiplies the rule's weight for that seller by 0.8 per click, floor 0.4; resettable. Stored in `user_rule_adjustment`.                                                                                                                                                                                    | Learns from feedback without silencing a rule entirely.                                                                                                                                                               |
| D-040 | **iOS-style UI** (large titles, inset grouped lists, bottom tab bar on phones, floating top tab bar on wide screens, sheets). Light and dark themes, **light by default** (`auth_user.theme`). No Apple trademarks or SF Symbols.                                                                                                 | Product owner direction; prototype `prototype/companion-ios.html`.                                                                                                                                                    |
| D-041 | Schema baseline **replaced** (migration `0001_schema` regenerated, `0002` rewritten) instead of forward migrations dropping tables.                                                                                                                                                                                               | Approved by the product owner; nothing was ever deployed.                                                                                                                                                             |
| D-042 | Voice dictation **off by default**, enabled per user after a notice.                                                                                                                                                                                                                                                              | Chrome's Web Speech API sends audio to an online service (MDN SpeechRecognition).                                                                                                                                     |
| D-043 | Seller-owned child rows reference parents through `(organization_id, owner_id, id)` composite FKs with ON UPDATE CASCADE.                                                                                                                                                                                                         | A child can never point at another owner's record; future ownership transfer moves the whole tree.                                                                                                                    |
| D-044 | AI provider key is **write-only** for the app role (column-level SELECT revoked).                                                                                                                                                                                                                                                 | Rule 6: secrets never returned after entry; tested.                                                                                                                                                                   |
| D-045 | The active organisation is stored on the Better Auth session row (`auth_session.active_organization_id`) and re-validated against an active membership on every request.                                                                                                                                                          | Per-session (two tabs/devices can work in different organisations); never trusted without a membership check.                                                                                                         |
| D-046 | Magic-link tokens stored **hashed** (`storeToken: "hashed"`), 15-minute expiry, single use; Better Auth rate limiting on (switch `AUTH_RATE_LIMIT=off` used only by the e2e server).                                                                                                                                              | A database leak cannot be replayed as sign-ins.                                                                                                                                                                       |
| D-047 | Outgoing mail refused unless the SMTP host is local (localhost / Mailpit / test sink) or `MAIL_ALLOW_EXTERNAL=true`.                                                                                                                                                                                                              | Encodes the "stop and ask before sending real email" rule.                                                                                                                                                            |
| D-048 | Invitations accepted through `accept_invitation()` (SECURITY DEFINER): token hash, expiry, single use, signed-in email must match; membership created inside the tenant context.                                                                                                                                                  | The invitee has no tenant yet, so RLS hides the invitation from them.                                                                                                                                                 |
| D-049 | End-to-end tests use their own SMTP sink (`smtp-server` + `mailparser`, dev-only) and a dedicated `clean_e2e` database reset by Playwright global setup; Mailpit stays the local development mail catcher.                                                                                                                        | Runs anywhere (no Docker needed), deterministic, nothing leaves the machine.                                                                                                                                          |
| D-050 | Server-side permission matrix in `src/domain/permissions.ts` (team view: admin/manager; invite, roles, team visibility, org settings: admin) checked in services; an admin cannot remove their own admin role.                                                                                                                    | Rule 2 "RLS plus API checks"; avoids lock-out.                                                                                                                                                                        |
| D-051 | Demo seed (`src/server/seed/`) writes through the app role with `withTenant` as each record's owner; re-running deletes only the fixed demo organisation id and `@lumendata.example` users. The e2e setup seeds the same book.                                                                                                    | RLS and auditing are exercised by the seed itself; the clean-up can never touch real data.                                                                                                                            |
| D-052 | `loadBook()` maps the seller's own rows (explicit `owner_id = me`, inside RLS) to the pure rules engine; Today renders `rankActions()` with translated reasons.                                                                                                                                                                   | Today stays personal even when team visibility lets a manager read more.                                                                                                                                              |
| D-053 | Account pages show the seller's own accounts only (owner filter on top of RLS); a teammate's account is a 404 even with team visibility on. A read-only team view is Phase 3.                                                                                                                                                     | "Seller's own workspace" first; avoids half-built shared editing.                                                                                                                                                     |
| D-054 | Tabs and filters are URL search params rendered on the server (`?tab=people`, `?tier=key&q=…`).                                                                                                                                                                                                                                   | Shareable, back-button friendly, works without client JavaScript.                                                                                                                                                     |
| D-055 | One action formatter (`src/components/app/action-format.ts`) turns rule reason codes into titles and reasons for Today, the account list and account pages.                                                                                                                                                                       | The same action always reads the same way everywhere.                                                                                                                                                                 |
